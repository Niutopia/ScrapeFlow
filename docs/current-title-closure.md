# 当前作品闭环

ScrapeFlow 的常驻产品只处理用户在 Web 提交的当前作品：

`提交目录 → 安全刮削 → 到盘复核 → 当前作品补源/字幕核验 → 到盘回刮 → 当前作品再复核`

## 任务边界

每个闭环都由一个用户任务拥有。媒体计划签名并确定 TMDB 身份后，任务只复核该作品的正式库根；不会因为一个任务启动扫描或治理其他作品。当主作品占用系列根、其他独立 ID 的作品位于子目录时，主 target 由同一签名计划派生稳定排序的 `excluded_roots`；字幕 inventory 和缺集扫描均通过只读过滤视图排除这些子叶，子作品仍作为独立 target 核验。

缺集优先处理。正片和 Season 00 缺口闭合后，系统再判断简体中文字幕。外挂字幕、内嵌字幕轨和内容证据仍无法形成结论时，才在内部调用烧录字幕 OCR。OCR 不替换、不重封装也不删除视频。

## 补源与到盘回刮

确定缺口使用当前作品的 request、candidate、selection、attempt 和 acquisition 工件选择来源。候选默认落入 `/quark/影视/ScrapeFlow/补源`；只有路径、名称、大小和内容身份通过校验，才创建绑定原任务的后续刮削。

后续刮削继承原任务的目标分类/父边界、canonical 作品叶子和已经确认的媒体身份。分类与身份不得互相推导：例如番剧目标中的大电影继续使用 `movie` 身份，但不能自动切换到电影分类。

候选资源失效只隔离该候选。网络、认证、配额、Helper 或存储故障保持为基础设施失败，不能伪装成“没有资源”。当前默认必需搜索证明是 PanSou 分享索引及 AnimeTosho、TokyoTosho 两个独立 Torrent 索引；Mikan、SubsPlease、Nyaa 和 ACG.RIP 作为附加覆盖，其是否完整响应会单独记录。必需来源已完整搜索仍无结果时，任务保持 `awaiting_sources`，按当前作品的 `next_review_at` 延后复查，不扫描其他作品。

Mikan 通过公开搜索 RSS 读取直接 Torrent enclosure，SubsPlease 通过公开 API 读取单文件 magnet。两者都必须经过与其他 Torrent 来源相同的 BTIH、文件路径、大小、季集和作品身份校验；网页标题命中不等于可交付候选。

字幕成员发现会在作品宽泛词、季词和精确集词之间公平分配单轮 metainfo 上限，并为每个来源、每个查询记录请求、响应、可用候选、入选候选和截断状态。一个宽泛 Mikan 页面不能在 `S00` 或精确集查询执行前耗尽全部名额。AnimeTosho、TokyoTosho 等必需来源完成后即可形成当轮必需搜索证明；若 Mikan 等可选来源仍有截断页面，后台按持久截止时间继续翻页，作品复核等待同一截止时间，不做 30 秒无证据重扫。可选来源网络故障继续记作基础设施失败，不得写成 0 命中。

## 复核与完成

每次媒体或字幕到盘后重新读取当前作品。只有签名作品根中的缺集和缺字幕都由新鲜证据证明消失，任务才完成。重启、重复提交或重试必须复用已有 journal 和来源身份，不得再次移动已成功文件。

## 必须保留的保护

1. 源目录、目标目录边界和重叠检查。
2. TMDB 身份不明确时停止自动执行。
3. 执行前重新读取 AList，确认源文件没有变化。
4. 目标同名文件存在时禁止覆盖。
5. 完整计划摘要校验，拒绝过期或串任务计划。
6. 临时重命名、路径锁和串行写入。
7. journal、断点恢复和失败回滚。
8. 残留只由 `residual_policy.py` 分类：外挂字幕先留给精确视频字幕闭包，未知文件不删；已确认的非正片也必须先经本机单文件缓冲写入夸克事务回滚区、全量回读 SHA-256 并封存批次 manifest，失败/取消时 restore，严格作品验收后才 commit。
9. 幂等任务、来源和写入，避免重复执行再次移动文件。

持久 `global-control.json` 是唯一暂停权威。暂停时不开始新的任务分析、作品复核、补源派发或写入；备份还需等待已经开始的远程动作静默。若暂停恰好截断作品审计后服务重启，恢复逻辑只重建等待器，并在全局恢复后继续同一作品，不能在暂停期间抢跑或遗失该轮复核。

## 一次性全库专项

全库补齐是单独的运维操作，只允许显式启动默认只读的审计/规划工具。它用于本次生成工作清单并暴露作品级流水线问题，不在 API 中周期运行，不拥有常驻协调器、Web 面板或自动全库清理。专项结束后，最多保留手工只读审计入口用于排查。
